# Private configured printers

The Android application stores printer bindings in the app-private `printer-instance` preference snapshot. This is an application persistence format, not an extension of `.tcfg` v1. Backup is disabled by the application manifest.

Version 2 atomically stores up to 32 configured Bluetooth Classic printers, the selected printer ID, and an optional imported profile used by Printer Management. Each configured printer owns its exact validated base-profile snapshot, typed override-presence mask and validated effective-profile snapshot, stable application ID, display name, private transport locator, profile ID/revision, and cut/feed defaults. Overrides preserve whole-field replacement and explicit clearing of printer-buffer guidance. Both snapshots pass the existing strict `.tcfg` reader and physical-profile validator on load. Identity/revision mismatches, duplicate IDs/locators, unavailable selections, invalid defaults and invalid effective profiles reject the snapshot.

Each encoded profile is bounded to 1 MiB; aggregate UTF-8 profile/metadata strings are bounded to 4 MiB. Metadata retains the `PrinterInstance` length/control-character limits. Defaults use printer dots, with zero additional feed and no automatic cut as safe defaults. The 100,000-dot feed ceiling is an application safety limit, not a measured tear-bar distance. Automatic cut defaults require support for the requested mode in the validated effective profile.

An imported profile is separate from saved bindings. Reimporting a profile, including the same identity with changed contents or revision, does not retarget existing printers. Explicit assignment replaces that printer's base snapshot and clears old overrides; incompatible cut defaults fall back to no cut/zero additional feed. Updating one printer leaves other bindings intact. Deleting the imported profile atomically removes bindings with its profile ID/revision and clears selection if affected. It preserves unrelated printers, drafts and Android pairing, and does not choose another printer automatically.

At startup, valid version 2 data is authoritative, including an empty snapshot with no imported profile. The old fixed-path `selected-printer.tcfg` file is only a migration source. A version 1 association migrates only with an exact matching, strictly validated legacy profile. Migration preserves its stable ID/transport identity and selects it with zero additional feed/no-cut defaults. A legacy profile without an association migrates as an imported management profile with no configured printers. A failed migration or unknown/corrupt version does not overwrite the old snapshot. An inert legacy file cannot resurrect deleted profiles or printers after version 2 exists.

Preference replacement uses synchronous commit and publishes success only after commit succeeds. On failure, the previous confirmed preference values are restored because Android's preference cache can otherwise expose failed writes. Configuration operations serialize and derive from confirmed persisted state. Pending operations invalidate the selected effective profile; only the newest request publishes selection/readiness. The prior confirmed configuration is republished on failure.

Bluetooth presence is an optional explicit refresh, bounded to ten seconds and independent of print readiness. Android 12+ requests CONNECT/SCAN; earlier Android versions request foreground location only for discovery. Scan results never establish a connected session or completed printing. A miss means not detected during discovery, and does not establish that a known printer cannot connect. Receivers are released and discovery cancelled on completion, cancellation, foreground loss and before connecting. Concurrent refreshes serialize cleanup. Presence refresh has no socket or command API and is skipped during an active connection. Transport startup checks that the saved selected instance/profile remains current.

Hardware behavior and physical output remain separate acceptance gates. These persistence/default/discovery rules make no claim about measured feeding, cutter hardware, RFCOMM compatibility or actual paper output.
